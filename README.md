# lover_chat

以你的身份自动回复微信消息的 agent。它通过网页版微信（wx2.qq.com）收发消息，用大模型模仿你的口吻回复指定的人和群，遇到拿不准的情况就停下来交给你。

> ⚠️ 微信个人号没有官方开放接口，任何自动化都违反《微信软件许可及服务协议》，有被限制登录或封号的风险。建议先用小号测试。替你回复的对象并不知道是程序在回，请自己掂量分寸。

## 能做什么

- **自动回复**：只盯配置里列出的联系人和群，其他消息一概不碰。回复前先等几秒，收齐对方连发的消息再回。
- **像你**：用人设、你说过的原话、最近 40 条聊天和长期记忆来生成回复。每次回复都是「先接住对方，再抛一个话题」。
- **和女生聊天**：规则来自对中文聊天建议和恋爱心理研究的调研（已剔除 PUA 套路），分「刚认识 / 暧昧 / 恋爱」三档分寸，附约 30 组示例对话。
- **长期记忆**：每攒 15 条新消息，自动整理出值得长期记住的事（对方的喜好、近况、带日期的计划、你们的梗、你说过的关于自己的话），存在 `data/memory_<对话>.json`，可以手动修改。
- **每个女生分开**：记忆（`data/memory_<key>.json`，`pinned` 是你手写的关键信息，永远不会被改写）、说话风格（`data/style_<key>_<阶段>.md`，按 `stage` 选）、邀约记录（`data/invites_<key>.json`）都按对话分开，互不串。
- **适时邀约**（`invite.py`）：每次回她之前，一个独立的判断模型看阶段、记忆和最近聊天，决定要不要约。不定时间地点的轻邀约（“下回去你那带我尝尝”）直接顺在回复里；具体到哪天去哪的，先发到文件传输助手问你，你回“发”就原样发出去。冷却期：刚认识/朋友 7 天，暧昧 3 天，恋爱 1 天。配置里 `invite: False` 关掉。
- **她约你、问你本人的事**：不替你答，在文件传输助手问你「她问你这周末有没有空吃饭，怎么回？」，你回了再照你的意思回她。
- **回复短一点**：配置 `max_chars` 后，每次回复的长度从你在这个对话里真实回过的长度里抽：大多数很短，偶尔长一点（长尾分布）。超长就重写；光附和一句（“可以啊”“挺好的”）、复读她的话、重复自己刚说过的梗，也会被拦下重写。
- **看图**：她发照片时，程序从网页微信下载原图，交给看图模型（Gemini 接口，配在 `.env`）描述成一两句话，再按图里的真实内容接话。看图失败时不猜，先在文件传输助手问你。
- **表情包**：`stickers/` 里每张图都先让看图模型写一句“它实际表达什么”，模型按这个挑；发之前看图模型再看一眼当下的聊天，不合适就不发（`sticker_check`）。
- **骚话先给你审**（`flirt.py`，`flirt_review`）：她在撩你、给了口子时，另一个模型写一句带点骚的，连同普通回复一起发到文件传输助手，你回“发”发骚的、回“普通”发普通的、或者直接写你想说的；几分钟没回就发普通的。
- **预演**：`.venv/bin/python tools/rehearse.py <key>`，你扮她打字，看程序怎么回、会不会约、会记住什么。不发消息，不写 data/。
- **主动开话题**：对话冷场一段时间后，接着之前聊过的事主动开口（可按对话开关，有每日上限和时段限制）。
- **多道把关**：
  - 生成后先过代码规则（不替你承诺、不编你的事、不复读、不重复自己的梗、不说 AI 腔），再交给模型审核员检查，不合格就重写。
  - 对方起疑、约见面、生气、谈钱时，转交给你。

## 你怎么控制它

| 操作 | 效果 |
|---|---|
| 在项目目录建 `PAUSE` 文件 | 全部暂停，删掉恢复 |
| 建 `RESUME` 文件 | 解除所有对话的暂停，并补回还没回的消息 |
| 在某个对话里亲自发言 | 那个对话暂停 10 分钟（可按对话设置，`0` 表示不暂停） |
| 在文件传输助手里写怎么回 | 程序转交后，照你的意思回。最准的用法是**引用那条转交提醒**再写，会回到那条提醒对应的对话；也可以开头写「对话名：」，或者直接写（回到最近一次转交的对话） |
| 建 `SAY` 文件，内容 `对话key|指示` | 跟在文件传输助手里写指示一样，比如 `her|原话发这句：……` 原样发出 |
| 在文件传输助手写不带「跟她说」的话 | 当成对回复风格的意见，记进这个对话的纠正（`corrections`），以后每次回复都照着来，不会发给她 |
| 改 `status.txt` | 告诉它你现在在干嘛，不用重启 |
| 以 `HUMAN_MARKS` 里的标记加冒号开头发消息 | 你自己的「本人发言」标记，程序永远不会用它 |
| Ctrl+C | 退出 |

## 安装

需要 macOS 或 Linux、Python 3.11+、Google Chrome，以及一个阿里云百炼（DashScope）的 API key。

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env              # 填 DASHSCOPE_API_KEY
cp config.example.py config.py    # 填你的人设和要自动回复的对象
```

`config.py` 里最影响效果的三样：

1. `ME`：你的基本情况。没写的事，模型只会含糊带过。
2. `MY_SAMPLES` 和每个对象的 `samples`：你说过的原话，越多越像你。
3. 每个对象的 `about`：你们的关系、对方的情况。

## 运行

```bash
.venv/bin/python bot.py
```

第一次会弹出一个 Chrome 窗口，用手机扫码登录网页版微信，登录状态保存在 `.wx_profile/`。网页版同一时间只能登录一处。如果开着代理，wx2.qq.com 偶尔会连不上，程序会自动重试。

## 聊天记录收集

程序一直在后台收集你的聊天记录，用来学你的说话风格（`data/corpus/`，每个对话一个文件，不进仓库）：

- 只收和她的对话（配置里 `kind: "girl"` 的对象），外加你在 `COLLECT_ONLY` 里手动列的；男生和群聊不收，程序也不会学你跟他们说话的方式
- 你的每条消息都记，别人的消息只在你回复时作为上下文记最近 10 条
- 每条标 `author`：`me`（你亲手发的，加没加暗号都算）、`ai`（程序发的）、`other`（别人）。程序认 AI 靠的是它自己发出的消息 ID（持久保存），不靠暗号
- `COLLECT_EXCLUDE` 里的对话不收
- 建一个 `PAUSE` 文件就是「只收集、不回复」模式

如果有 `data/style_<对话>.md`（手工蒸馏的风格说明 + 挑过的真实片段 + 不要学的说法），程序优先用它；没有的话，和她聊天时程序只从你们自己的对话里挑你真实的一来一回当示范（排除暗号消息和聊 agent 本身的内容），把聊天按一来一回的对话轮次交给模型，让它直接以你的身份接着聊。

## 守护进程

```bash
./botctl.sh install    # 注册成 macOS 守护进程并启动：崩溃自动重启，登录后自动启动
./botctl.sh stop       # 停止（不会被自动拉起）
./botctl.sh start | restart | status | log
./botctl.sh uninstall  # 停止并取消开机自启
```

和直接 `.venv/bin/python bot.py` 是同一个程序，区别只在于由 launchd 托管。两种方式别同时跑：网页版微信只能登录一处，会互相挤下线。

## 表情包

把 GIF 放进 `stickers/`，文件名就是表情包的名字（比如 `笑死.gif`），程序会把可用的名字告诉模型，模型在回复里单独一行写 `[表情包:笑死]` 就会发出去，对方收到的是真正的表情包。建议 240×240、500KB 以内。以 `_` 开头的文件只用于测试，模型看不到。启动时设 `LC_STICKER_TEST=名字` 会把那张表情包发到你的文件传输助手，用来检查发送是否正常。

`stickers/` 不进仓库。作者自用的那套来自 Google 的 [Noto Animated Emoji](https://googlefonts.github.io/noto-emoji-animation/)，授权 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)，已缩放并重新编码为 GIF。

## 测试提示词

```bash
.venv/bin/python tools/eval_girl.py v3
```

用 20 个女生聊天场景 × 2 种关系阶段跑一遍回复流程，结果存到 `data/eval_v3.txt`，可以和之前的版本对比。这一步不会发出任何消息。

## 工作原理

```
wx2.qq.com（Playwright 控制的 Chrome）
  └─ hook.js 挂在网页版的 chatFactory.messageProcess 上，把新消息推给 Python
bot.py：匹配对象 → 记录 → 等对方说完 → reply.compose()
  reply.py：起疑/约见面检查 → 生成 → 代码规则 → 审核员 → 合格就发，不合格重写或转交
  memory.py：后台整理长期记忆
  llm.py：DeepSeek（DashScope OpenAI 兼容接口）
发送：hook.js 里的 __lcSend 调网页版自己的发送流程
```

## 目录

| 文件 | 作用 |
|---|---|
| `bot.py` | 主程序：浏览器、消息分发、暂停/转交/主动开话题 |
| `hook.js` | 注入网页版微信的收发钩子 |
| `reply.py` | 生成、检查、审核、重写 |
| `prompts.py` | 所有提示词和代码规则 |
| `memory.py` | 长期记忆 |
| `llm.py` | 模型调用 |
| `config.example.py` | 配置模板 |
| `tools/eval_girl.py` | 女生聊天测试集 |
